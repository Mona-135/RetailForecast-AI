# Hadoop HDFS Storage Architecture & Operations

## 1. Overview of Hadoop Architecture

Hadoop Distributed File System (HDFS) is designed to reliably store large datasets across commodity hardware:

### NameNode (The Metadata Master)
- **Role**: Manages the filesystem namespace, directory hierarchy, and metadata.
- **Responsibilities**: 
  - Keeps track of all files, directories, permissions, and block allocations.
  - Knows which DataNodes hold the physical blocks for each file.
  - Maintains the transaction log (`EditLog`) and filesystem image (`FSImage`) in memory and on disk.
  - If the NameNode is unavailable, the cluster becomes inaccessible unless a Secondary or High-Availability NameNode is configured.

### DataNode (The Block Storage Worker)
- **Role**: Stores and retrieves the actual data blocks as instructed by the NameNode or client.
- **Responsibilities**:
  - Periodically sends Heartbeats and Blockreports to the NameNode to confirm health and block inventory.
  - Handles block creation, deletion, and replication pipelining.
  - Reads and writes block streams directly to and from PySpark or Kafka consumers.

## 2. Directory Layout in HDFS

The retail forecasting pipeline organizes files into the following canonical HDFS paths:

| HDFS Directory Path | Description |
|:---|:---|
| `/retail/raw/` | Raw ingested Walmart CSVs (`train.csv`, `features.csv`, `stores.csv`) and Kafka-streamed JSONL batches |
| `/retail/processed/` | Cleaned, deduplicated, and typed sales datasets saved as columnar Parquet |
| `/retail/features/` | Engineered lag features, rolling statistics, and calendar attributes |
| `/retail/predictions/` | Output predictions and forecasts generated by ML models |

## 3. Essential HDFS Terminal Commands

All commands can be executed inside the `namenode` container or via local `hdfs` client:

### A. Initialize HDFS Directory Hierarchy
```powershell
# From host machine using Docker:
docker exec -it retail-namenode hdfs dfs -mkdir -p /retail/raw
docker exec -it retail-namenode hdfs dfs -mkdir -p /retail/processed
docker exec -it retail-namenode hdfs dfs -mkdir -p /retail/features
docker exec -it retail-namenode hdfs dfs -mkdir -p /retail/predictions
```

### B. Upload Raw Walmart Datasets to HDFS
```powershell
docker cp data/raw/train.csv retail-namenode:/tmp/train.csv
docker exec -it retail-namenode hdfs dfs -put -f /tmp/train.csv /retail/raw/
```

### C. Verify Directory Hierarchy and Stored Blocks
```powershell
docker exec -it retail-namenode hdfs dfs -ls -R /retail
```

### D. Read First Records Directly from HDFS
```powershell
docker exec -it retail-namenode hdfs dfs -cat /retail/raw/train.csv | head -n 10
```

### E. Download Processed Forecasts from HDFS to Local Disk
```powershell
docker exec -it retail-namenode hdfs dfs -get /retail/predictions /tmp/predictions
docker cp retail-namenode:/tmp/predictions ./data/predictions
```
